### S0 · 地基：`format_core` 骨架 + 能力探测（0.5 天）—— ✅ 已完成 2026-10-21

这一步不加任何界面，只把结构立住。

**做什么**
1. 新建 `packages/format_core/`（纯 Dart，**不 import Flutter**）：

3. 新建 `lib/convert/job_queue.dart` 接口（先只有串行实现，S5 再填批量语义）
4. 探针脚本 `tool/formats/probe_matrix.sh`：用**主机 ffmpeg** 对每个格式跑一遍编码，
   输出 `tool/formats/matrix.md`（哪台机器缺什么一眼可见）

**不做**：任何转换 UI、任何格式实现。

**验收**

**实际交付**

### S1 · 视频转音频（0.5–1 天）—— ✅ 已完成 2026-10-21

**为什么第二个做**：用户最想要、技术最简单（`-vn -c:a copy` 实测 rc=0），
同时它是**第一个用完整个纵切**（命令 → 服务 → 界面 → 存相册）的功能，
能提前暴露编排问题，代价最小。

**做什么**
1. `commands.dart`：`extractAudio({input, output, codec, copy})`
   - m4a：容器兼容时 `-c:a copy`（零损失、秒级）
   - mp3/flac/wav：分别 `libmp3lame -q:a 2` / `flac` / `pcm_s16le`
2. `services/audio_extract_service.dart`：选路（能 copy 就 copy）、时长读取、失败清理
3. `screens/extract_audio_screen.dart`：选视频 → 显示时长/码率/估计大小 → 选格式 → 出文件
4. 文案：copy 路径显示「无损提取（不重新编码）」

**不做**：剪辑、变速、多轨、批量。

**验收**
- ✅ 设备实测（`integration_test/ffmpeg/extract_audio_device_test.dart` 4/4）：probe 报告音轨、
  **copy 保持 codec aac 与时长**、mp3 重编码时长一致、无音轨视频被识别
- ✅ host 测试：命令形状 3 条 + 界面 6 条 + 摘要 4 条 + 音频预估 3 条 + 首页 2 条
- ✅ 真机截图 `tugi_extract_audio.png`：「无损提取（不重新编码）」+ 预估 120.3–126.5 KB

**实际交付**
- `lib/ffmpeg/audio_commands.dart`：`extractAudio`（`-vn -map 0:a:0`，copy 与重编码两种形状）
- `lib/services/audio_extract_service.dart`：`probe()`（FFprobeKit：时长/codec/码率/声道）、`extract()`
- `lib/screens/extract_audio_screen.dart`：源卡 + 格式网格 + 无损徽标/码率滑杆 + 预估 + 结果
- `packages/format_core/src/audio_copy.dart`：`canStreamCopyAudio` 策略（aac↔m4a、mp3↔mp3、pcm↔wav…）
- 首页新增第 10 个入口「Extract Audio」，新增 `Accents.cyan`（未来「转换」分类的颜色）

**过程中修掉的真 bug**：首版把 ffprobe 的 `getChannelLayout()`（返回 `stereo`/`mono` 名字）当整数解析，
界面显示「0 声道」。已改为按布局名映射，并加了 4 条回归测试。

### S2 · JXL 构建验证（1–2 天，可与 S1/S3 并行）

**为什么单独成步**：这是我们唯一需要**自己编译原生库**的地方，不确定性最高；
先花两天把不确定性消掉，再决定 S3 的抽象形态。失败也有 Plan B。

**做什么**
1. 用 [ffmpeg-kit-next](https://github.com/arthenica/ffmpeg-kit-next) 的构建脚本，加 `--enable-lib-libjxl`，
   **先只建 `arm64-v8a`**（模拟器 x86_64 单独建一次用于测试），产出 AAR
2. 先做**解码优先**：`cjxl` 编码慢（AV1/DCT 混合），移动端主要诉求是「能打开 .jxl」；
   编码作为可选能力，UI 允许但标注耗时
3. 接到当前工程（本地 package 或 `subprojects` 换 AAR），验证：
   - `-encoders | grep jxl` 出现 `libjxl`
   - JXL → PNG、PNG → JXL 往返，像素/尺寸正确
   - 记录 APK 体积增量（预期 +3–5 MB/ABI）
4. 结果写进 （JXL 构建报告，未落盘）：构建命令、依赖、体积、性能数字

**Plan B（若 2 天内建不出来）**：改用「Flutter 插件 + 系统 libjxl 预编译 .so」，
S3 里保留 `外部编解码器` 抽象即可，不影响其它步骤。

**不做**：JXL 动画、无损模式细调、并行编码调参。

**验收**
- 设备上 `test/device` 或一次探针：JXL 读 + 写两条链路 rc=0
- APK 体积与耗时记录在案
- 决定并记录：S3 是否需要「外部编解码器」分支

### S3 · 转换核心 + 单文件转换界面（3–5 天）—— ✅ 已完成 2026-10-21

**这是本项目的核心一步**，做完就有「万能格式转换」的最小可信版本。

**做什么（按内部顺序）**
1. **图片路径**：`convertImage`
   - 输入：PNG/JPG/WEBP/AVIF/GIF/APNG/BMP/TIFF/J2K/QOI/ICO/PSD/EXR/TGA/PCX/DDS（按能力探测结果置灰）
   - 输出：PNG/JPG/WEBP/AVIF/GIF/APNG/BMP/TIFF/J2K/QOI/ICO/TGA（+JXL，若 S2 成功）
   - 参数：质量（有损格式）、背景色（透明→不透明时）、保留/丢弃动画帧
2. **音频路径**：`convertAudio`（复用 S1 的服务，扩到 mp3/aac/m4a/flac/ogg/opus/wav 互转）
3. **视频路径**：`convertVideo`
   - 容器：mp4/webm/mkv/mov/avi；编码：h264/h265/vp9/av1（av1 标注「很慢」）
   - 参数：分辨率、帧率、CRF/码率、音频保留/去掉
   - 大文件时提示可切 `h264_mediacodec`（硬编）
4. **预估**：图片按 bpp 模型（需先跑一次标定脚本得到每格式每质量档的 bpp 区间）；
   音频按码率×时长（精确）；视频给区间或「目标体积模式」
5. **界面** `format_convert_screen.dart`：源自适应 → 目标格式网格 → 参数 → 预估 → 转换 → 结果
6. 边界规则（都在代码注释里写明理由）：
   - 多帧 → 静图：取首帧并提示
   - 透明 → JPEG/BMP：自动垫背景色（可改）
   - 超大图（> 8000px 边长）走 `-vf scale` 降采样保护内存

**不做**：批量（S5）、HEIC（S6）、编辑类功能。

**验收**
- ✅ 设备（`integration_test/ffmpeg/convert_device_test.dart` 4/4）：透明 PNG→JPEG **垫白成功**、
  GIF→PNG 只取首帧、MP4→WebM(VP9)、M4A→MP3
- ✅ host 测试：命令形状 15 条、界面决策 9 条、图片预估 6 条
- ⚠️ 「12 格式全矩阵」拆到 S3.1：本步先把三条路径与界面打通，
  逐格式矩阵由 `tool/formats/probe_matrix.sh` 在主机侧先兜住（28/28），设备侧按需逐格式补

**实际交付**
- `lib/ffmpeg/convert_commands.dart`：`convertImage` / `convertVideo` / `convertAudio`
  - 透明→JPEG/BMP **垫色**用 `[1:v][0:v]overlay` + `format=rgb24`（颜色源用 `0xRRGGBB`，
    因为 `#` 在滤镜图里是注释起始符——第一版就是这么错的）
  - 视频：CRF 由质量策略换算；WebM 自动用 Opus（AAC-in-WebM 播放器不认）；
    硬件编码把 CRF 换成码率（MediaCodec 不接 CRF）
- `lib/services/convert_service.dart`：`probe()` 用 ffprobe **按内容**判定 图片/动图/视频/音频
  （`.gif` 里装的是 JPEG 也按 JPEG 处理）、是否有音轨、是否有 alpha；`convert(ConvertRequest)` 三分支
- `lib/screens/format_convert_screen.dart`：源卡 → 格式网格 → 参数 → 预估 → 转换 → 结果
- **图片预估模型**（`estimateImageBytes`）：无损格式按像素算（BMP 精确 = 3×w×h，
  TIFF 3–7.5 bpp，EXR 8–26 bpp）；有损格式给**源文件的倍数区间**，因为实测同样参数下
  照片 1.77 bpp、纯色 0.0135 bpp（130 倍差距），按像素预测没有意义
- 新增第 11 个首页入口「Format Convert」

**过程中修掉的真 bug**
1. 垫底色用 `color=c=#ffffff`：`#` 是滤镜图的注释起始符，必须写 `0xffffff`；
2. 硬件编码判断写成 `encoder.contains('mediacodec')` —— `List<String>` 里当然没有这个元素，
   条件永远为假，硬件开关点了没反应；
3. 设备用例里用「视频流 codec」检查 MP3 输出（MP3 没有视频流），改成检查音频流。

**S4.14 文本选择手柄与顶区手势冲突（2026-10-22 夜）**
- 现象：搜索框/水印输入框里长按选中文字后，拖动选择手柄会把设置面板拉出来。
- 原因：选择手柄的拖动也是横向拖拽，祖先的顶区识别器把它抢走了；**只是"忽略"手势不够**——
  识别器照样在手势竞技场里赢、手柄拿不到事件。
- 修法：`SettingsHost` 监听 `FocusManager`，**有 `EditableText` 获得焦点时根本不挂载**顶区识别器，
  手柄独占手势；此时齿轮图标仍可打开设置。
- 测试：聚焦的 `TextField` 上向右拖拽不得打开面板。

**S4.13 背景替换真因 / 搜索复位 / 选中菜单中文（2026-10-22 夜）**

### S9 · 滤镜第一批（4–6 天）

**关键决策：滤镜用 ffmpeg 实现**，而不是纯 Dart 像素运算。原因：我们本来就带 ffmpeg，
`eq`（亮度/对比/饱和度）、`curves`、`unsharp`、`gblur`、`lut3d`（.cube LUT）都是现成的，
且支持 GPU/多线程；纯 Dart 处理 4000×3000 会卡到不可用。

**做什么**
1. 20 个常用滤镜（亮度、对比、饱和、色温、锐化、模糊、暗角、黑白、反色、复古、鲜艳、胶片×3、LUT 导入）
2. LUT：`.cube` 文件导入 → 存 App 目录 → `lut3d` 应用；带缩略预览
3. 链式组合（最多 5 个，避免图过长）
4. 预览：低分辨率代理图（长边 720）实时预览，导出走原分辨率

**不做**：310 个滤镜全量、模板滤镜、GPU 着色器自定义。

**验收**
- 20 个滤镜逐个出图 + 视觉对比截图
- LUT 导入后与原图对比（同一 .cube 在主机 ffmpeg 上跑一遍，结果一致）

## 9. 品牌与视觉规范（2026-10-21 已定）

### 9.1 名字

- **Tugi（图叽）**。英文名用于包名/仓库/桌面图标下方文字，中文「图叽」作副标题与关于页。
- Dart 包名与 `applicationId` 建议：`tugi` / `app.tugi`（S4 一次性替换，见 S4 步骤）。

### 9.2 图标：几何 + 多色，Google 式

- **形态**：纯几何构成（圆 / 圆角矩形 / 三角 / 弧线），不用拟物、不用描边细字。
- **配色**：多色但不花——沿用 Google 三原色系的**低饱和版本**：蓝 `#4285F4`、绿 `#34A853`、
  黄 `#FBBC05`、红 `#EA4335`，外加品牌主色（建议青绿 `#12B5A6`，承接「转换」分类）。
- **构图**：正中一个「叽」（鸟喙/弧线）抽象形，四个几何块围绕；外层是圆角方形底板（自适应图标前景层），
  背景层用纯浅色（`#F5F6FA`，与现有 `Neutrals.bg` 一致）。
- **自适应图标**：前景 108dp 安全区内构图；同时出 `monochrome` 版（单色剪影），供 Android 13+ 主题图标。
- **尺寸**：`ic_launcher` 各密度 + `ic_launcher_foreground` 108dp + `ic_launcher_monochrome`。

### 9.3 动态彩虹光效（用户明确要求）

用在两处，且**只用在两处**，避免全屏乱闪：

1. **主 CTA 按钮**（如「开始转换」「添加水印」「导出」）：按钮边框 + 外发光沿边缘流动。
2. **关键容器边框**（预览舞台、结果卡片）：细描边做彩虹渐变流动，静态区域不动。

实现约束（写进代码注释，S4 落地时照做）：

- 用 `SweepGradient` + `ShaderMask`/`CustomPainter`，动画只驱动 `AnimationController` 的 `t`
  （0→1 循环，周期 3–4 s），**不重建子树**，只 `repaint` 画笔（`RepaintBoundary` 包住）；
- 颜色不硬编码：从 `AppPalette` 的彩虹序列取，保证与主题一致；
- **性能**：只在按钮可见时跑动画（`TickerMode`/路由可见性），列表里禁止每个 item 都挂一个；
  低端机（`MediaQuery.disableAnimations` 或省电模式）自动降级为静态渐变描边；
- **可达性**：动效不能是唯一的状态指示（禁用态必须是灰的、且无动画）；
- 一次只让「一个」主 CTA 有动效，页面里出现两个会显得廉价。

### 9.4 与现有设计系统的关系

- 现有 9 个功能的强调色（`app_palette.dart` 的 `Accents`）**保留**，但在 S4 按分类收敛为 4 组：
  转换=青、GIF=玫红、图片=蓝、工具=中性灰；
- 深色模式**不做**（见 §8），但要保证所有新颜色在浅底上对比度 ≥ 4.5:1。
