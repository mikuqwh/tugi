# 保存动作：按导出类型选择去处 — 2026-10-21

> 用户报障：视频转音频页面的「存到相册」对音频必然失败（相册没有音频），
> 点「分享」倒是能丢进文件管理器。问能不能按类型自动弹出合适的保存位置。
> 状态：已修，并且把同样错了的三个功能一起修掉。

## 一、根因不是「音频」一个功能

排查发现 `Gal.putImage` 被 8 个地方调用，其中 **4 处可能产出非图片**：

| 功能 | 输出 | 旧代码 | 结果 |
|---|---|---|---|
| Extract Audio | mp3/m4a/flac/wav… | `putImage` | **必失败**（就是用户报的） |
| Format Convert | 视频 / 音频 | `putImage` | 失败 |
| Add watermark（视频源） | mp4 | `putImage` | 失败 |
| GIF→Video / Images→Video | 视频 | `putVideo` | 正确 |

也就是说这不是「音频特例」，是「保存动作按类型分流」这件事一直没做。

## 二、方案：一个 `ExportService`

按**输出文件的实际格式**决定去处（不看功能、不看界面文案）：

| 类型 | 去处 | 实现 |
|---|---|---|
| 图片 | 系统相册 | `Gal.putImage` |
| 视频 | 系统相册 | `Gal.putVideo` |
| 音频（及未知） | **系统「保存到…」对话框**，可选 Music/Downloads | `ACTION_CREATE_DOCUMENT` |
| 图片/视频被相册拒绝 | 回退到保存对话框 | — |

- 按钮文案跟着变：相册类显示「存到相册」，音频类显示「**保存到文件**」；
- 取消对话框 = 取消（不是错误）；两个去处都失败才报错；
- 保存对话框预填**可读文件名**（`clip_audio.m4a`，不是 `audio_1792597974237.m4a`）。

### 为什么自己写平台通道而不是引插件

加插件需要 Windows 开发者模式（符号链接），本机没开、也不该为了一个动作去改系统设置。
所以直接在主 Activity 里写了一个方法（`tugi/export` 通道），约 60 行 Kotlin：

- `ACTION_CREATE_DOCUMENT` + `startActivityForResult`；
- 文件**在原生侧读取**再写入用户选的位置——否则 50 MB 音频要跨两次 JNI；
- 不需要任何存储权限（这是 SAF 的价值）。

> 一个坑：`registerForActivityResult` 在本项目的 Activity 基类上不可解析，改用经典的
> `startActivityForResult`（同样一个对话框，同样不需要权限）。

## 三、验证

| 项 | 结果 |
|---|---|
| `flutter analyze` | 0 error / 0 warning |
| host 测试 | **338/338**（原 326：+12 导出路由） |
| 真机 | 抽取音频 → 点「保存到文件」→ **系统对话框弹出**，预填 `audio_…m4a`，可选 Downloads/Music（截图 `tugi_save_dialog.png`） |
| release | EXIT=0，255.5 MB，已装模拟器 |

单测覆盖的是**路由决策**（用假实现注入）：音频永不调用相册、视频走 putVideo、
相册拒绝时回退、取消不算失败、文件不存在时不触碰任何去处。

## 四、仍然存在的限制

1. **SAF 对话框无法自动化**：只能人工点一下确认。设备测试覆盖到「对话框弹出」为止。
2. 视频体积很大时（>100 MB），原生侧会整块读进内存再写。音频与图片没问题；
   视频若相册拒绝后回退到对话框，内存占用会明显。后续可改成流式复制。
3. `Gal.putImage` 对 WebP 是否稳定由 gal 的实现决定；失败会自动回退到保存对话框，不会报死。
