> 状态：已按该交互落地 4 个功能，另有 3 个按代价延期（原因见 §4）。

## 一、交互：一个可复用的选择器

新组件 [lib/ui/output_format_picker.dart](impl/lib/ui/output_format_picker.dart)：

- 只摆「常用」的几个 chip；其余收在 **「更多格式 (N)」** 后面，点开变「收起」；
- **被选中的格式永远可见**——哪怕它属于「更多」。否则收起后当前选择看起来丢了，
  下面的说明文字还在描述一个看不见的格式；
- 本机 ffmpeg 写不了的格式**置灰 + tooltip 说明**（沿用能力探测），不隐藏。

## 二、接入的功能

| 功能 | 常用 | 更多 | 说明 |
|---|---|---|---|
| **GIF → 视频** | MP4·H.264 / H.265 / WebM·VP9 | MKV·H.264、MOV·H.264、AVI·MJPEG | 输出只列**视频容器**：GIF 没有音轨，列出 MP3/WAV 是坏承诺（第一版截图就是这么错的） |
| **GIFs to Images** | PNG / JPEG / WebP | BMP | 只列 Flutter 能再解码的格式，因为抽完帧要在网格里预览 |
| **Add watermark**（图片源） | PNG / JPEG / WebP | AVIF / BMP / TIFF | 动图源不提供（APNG 需要无调色板的另一条出口，见 §4） |
| **Add watermark**（视频源） | MP4·H.264 / H.265 / WebM | MKV / MOV / AVI | |
| **Edit Image** | 原始 / JPG / PNG / WEBP | — | 4 个选项，直接用原有 chip 行，不需要折叠 |

命令层改动全部**保持旧默认**：不传格式时，GIF→视频仍是 H.264 MP4、GIF→图片仍是 PNG、
水印仍是 png/gif/mp4——旧测试一条没改就全绿，这本身就是回归证明。

## 四、延期的部分（其中 APNG 已于 2026-10-22 补完）

> 更新：APNG 输出已在三处补完（Video→GIF、Images→GIF、Edit GIF）+ 水印动图源，
> 详见 [TUGI-APNG与多容器-20261022.md](TUGI-APNG与多容器-20261022.md)。
> 下述第 1、3 条已完成，第 2 条（Images to Video）同日完成于同一文档。

### 原始记录（2026-10-21）

1. **Video→GIF / Images→GIF / Edit GIF 的 APNG**：这三个功能的出口都是「调色板尾巴」
   （`split/palettegen/paletteuse`），APNG 不能走这条尾巴，得给每个功能加一条无调色板分支。
   只给 GIF 加一个「更多」项、且要改三条管道，收益不匹配，放到 S13（GIF 家族扩展）一起做。
2. **Images to Video**：它的实现是「每张图先编码成一段，再用 `-c copy` 拼接」。
   换编码器意味着段编码和容器要同时换（VP9 只能进 WebM，H.265 要 `-tag:v hvc1`），
   而拼接是零重编码的流复制——改错会静默产出坏文件。需要单独一轮验证，没放进这次批量改。
3. **Add watermark 的动图源**：同上，APNG 分支问题。

## 五、踩到的两个坑（都已修）

1. **选择器把「更多」里的当前项藏了**：收起后用户看不到当前选择，但下方说明还在讲它。
   修法：`common + selected` 恒定可见。
2. **GIF→视频列出了音频格式**：`formatsFor(MediaKind.video)` 是给转换器的
   （视频可以抽音频），直接拿来给 GIF→视频用就出现了 MP3/WAV 这种选不出的项。
   修法：筛选 `f.kind == MediaKind.video`。
