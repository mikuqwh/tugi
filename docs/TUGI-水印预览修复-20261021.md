# Add watermark 预览布局修复 — 2026-10-21

> 用户报障：选一张手机截屏（1080×2400）后，图片占满整页，下面的控件拖不动。其他功能无此问题。
> 结论：已修复并提交 `impl` 仓库 `300ab7a`。release 已重建，`impl\dist\app-release.apk` 为新包。

## 一、根因

`Add Watermark` 的预览是 `AspectRatio(aspectRatio: 源宽/源高)`。截图比例约 0.45，宽度撑满后高度要 ~2400px，
外层 `Column` 直接溢出，`Expanded(child: 控制面板)` 分到的高度为 0 —— 面板不是「滚不到底」，而是根本没有可滚动的盒子。

复现证据（旧代码上跑新测试）：`RenderFlex overflowed by 1199 pixels`，且 `wm_apply` 按钮**根本没有被构建**。

## 二、修法

预览改成高度封顶的 `LayoutBuilder`，与 Edit Image 屏同一套契约（那次是 `e55960d`）：

```dart
final screenHeight = MediaQuery.sizeOf(context).height;
final maxStage = _draggingWatermark
    ? math.min(420.0, screenHeight * 0.62)   // 拖动中：临时放大
    : math.min(300.0, screenHeight * 0.42);  // 静止：让位给面板
var w = box.maxWidth;
var h = w / aspect;
if (h > maxStage) { h = maxStage; w = h * aspect; }
```

- 保持源比例（不拉伸），只压高度；`Stack` 仍然精确填满 frame 盒，所以「Stack 的比例 = frame 的比例」这条
  拖动/水印定位的前提不变，ffmpeg 的分数坐标一行没动。
- 额外用屏幕高度的 42% 兜底：横屏手机只有 ~360 逻辑像素高，固定 300 会再溢出 32px —— 同一个 bug 换个方向而已。
- **拖动时临时放大**（按用户选择）：`onPanStart` 置位、`onPanEnd`/`onPanCancel` 复位，舞台上限 300 → 420
  （竖长图面积约 1.4 倍），面板由 `Expanded` 自动让出高度，松手恢复。用重建而不是动画：缩放要赶在下一个
  拖动回调之前生效，否则指针会按旧盒子映射、水印慢手指一帧。

新增 6 条 host 用例（前 5 条在旧布局下必失败，第 6 条在「放大过头」时必失败）：

1. 竖长图：stage ≤ 300，宽高比不变，面板高度 > 150，副标题在屏内
2. 竖长图 + 横屏 800×360：stage < 屏高一半，面板仍有空间
3. 竖长图：面板能滚到 `wm_apply`
4. 4:1 全景图：仍占满宽度（封顶只对高图生效）
5. 竖长图：在窄预览上仍能拖动水印（出现「自由」徽标），且拖动中舞台变大、松手复原
6. 横屏拖动：放大后不得溢出（把上限改成 0.95 屏高即复现 74px 溢出、面板高度 0）

实测数据（emulator-5554：720×1280 @160dpi，dpr 1）：静止 stage 300×136，拖动中 420×189，
两种状态都精确等于上限值；`420 > 0.62×1280`，说明该设备走的是 420 分支。

## 四、给下一个人的两条坑

1. **`testWidgets` 里不要直接 `await` 真实文件 I/O。** 上一轮的回归测试就是因此挂死（不是失败，是不结束）：
   post-frame 回调里 `await File(...).readAsBytes()` 在 fake async 区永远不会完成。已实测最小复现。
   现在用 `AddWatermarkScreen.loadSourceForTest()`（`@visibleForTesting`）在 `tester.runAsync` 里驱动**生产加载路径**。
2. **设备的 `add_watermark_ui_test.dart` 原来用 `find.byType(AspectRatio)` 定位预览**，布局换掉后失效，
   已改为 `find.byKey(Key('wm_stage'))`。改预览结构时记得同步它。

## 五、观感上的取舍（如需可再调）

竖长图静止时预览很窄（1080×2400 塞进 300px 高就是 135px 宽），文字水印只有几像素高；**拖动时**舞台放大到
420 高（约 1.4 倍面积），放得下也看得清，松手回落。若觉得还不够，可以把拖动上限 420 继续抬（横屏安全余量
由 `0.62` 那项兜着，实测 0.95 会溢出，0.62 在 360 高的横屏上仍留 ~47px 面板），或者让面板在拖动时整体折叠成
一条数值条（Edit Image 就是这么做的，代码在 `_buildDragBar()`）。
