## 一、APNG 输出（S13 的第一部分）

### 做了什么

四个功能现在可以输出 **APNG**（真彩、精确 alpha、无 256 色限制）：

| 功能 | 接入点 |
|---|---|
| Video → GIF | `videoToApng`（单趟，`fps=` 一次到位） |
| Images → GIF | `apngFromFrames`（concat 帧序列，保留原时长） |
| Edit GIF（变速/倒放） | `editGifSpeed` / `editGifReverse` + `format` |
| Add watermark（动图源/动图水印） | `addWatermarks` 的 `isApng` 分支 |

三个 GIF 屏幕加了「GIF / APNG」选择器；水印屏在动图输出时同样出现。

### 三个关键决定

1. **APNG 不走调色板尾巴**。`split;palettegen;paletteuse` 会把真彩量化成 256 色——那正是 APNG 存在的意义所在。
2. **不清洗时间戳**。concat 列表里已经写着每帧 `duration`，再套 `fps=` 或 `-r` 会二次重采样：
   host 实测 4 帧 / 0.083 s 的序列在 `fps=12` 下变成 3 帧。所以 APNG 路径不加这两个参数，
   只有视频源那条路才需要 `fps=`（源的时基不是我们要的）。
3. **循环用 `-plays`**，GIF 的 `-loop` 对 APNG 无效。

### 验证

- host：`test/ffmpeg/apng_output_test.dart` 9 条（无调色板、无 `-r`/`fps=`、`-plays` 0/1、
  GIF 老路径不动、视频 kind 仍走视频编码器）
- 设备：`integration_test/ffmpeg/apng_device_test.dart` 2/2
  - 视频 → APNG：codec=apng、帧数 9–11（1 s @10 fps）
  - GIF → APNG（倒放）：codec=apng、**帧数仍是 5**

## 二、Images to Video 多容器

### 做了什么

支持 **MP4·H.264（默认）/ MP4·H.265 / WebM·VP9 / MOV·H.264 / MKV·H.264**（AVI 没做，见下）。

这条管道是「每张图渲染成一段 → `-c copy` 拼接」，所以格式必须在**第一段渲染前**就定下来，
不能等到拼接时再改：

- 段编码器 = 目标格式的 `encoderArgs`（H.265 带 `-tag:v hvc1`，每个段都要有）；
- 段容器：WebM 用 `.webm`（VP9 不该进 mp4），其余仍用 `.mp4`，由拼接时换容器；
- 拼接：`muxer` 由格式决定（webm/matroska），`+faststart` 只在 mp4/mov 上加。

### 两个坑（都修了）

1. **成功判定的容器头只认 mp4**：`_looksLikeMp4` 找 `ftyp`，WebM/MKV 输出会被判成「无效视频」。
   改成按扩展名识别三种 magic：`ftyp`（mp4/mov）、`1A 45 DF A3`（EBML/webm/mkv）、`RIFF`（avi）。
   这个检查本身是为了挡住「ffmpeg 退出码 0 但只留 261 字节空壳」的坑，不能删。
2. **AVI 不做**：`-c copy` 把 H.264 塞进 AVI 在设备上没有把握（AVI 的 H.264 支持历来是灰色地带），
   宁可少一个选项，也不产出坏文件。选择器里已排除。

### 验证

- host：`test/ffmpeg/images_to_video_containers_test.dart` 7 条
- 设备：`integration_test/ffmpeg/images_to_video_containers_device_test.dart` **3/3**
  - mp4_h265 → codec=hevc、时长 ≈3 s
  - webm_vp9 → codec=vp9、时长 ≈3 s
  - mkv_h264 → codec=h264、时长 ≈3 s
- host 侧先单独验证过三种拼接（VP9 webm 段、mp4 段拼 mov、mp4 段拼 mkv）

## 三、S3.1 全格式设备矩阵（上次延期的那个）

### 是什么

S3 只验证了四个代表性转换（透明 PNG→JPEG、GIF→PNG、MP4→WebM、M4A→MP3），
当时把「12 格式 × 设备全矩阵」明确延后。这次补上：

`integration_test/ffmpeg/convert_matrix_device_test.dart` 遍历注册表里**每一个**可用格式，
用一张小图 / 一段正弦音 / 一个小视频作源，逐个真转，再用 ffprobe 校验产物 codec。

### 结果：28/28 全部通过

| 类别 | 数量 | 覆盖 |
|---|---|---|
| 图片 | 15 | png, jpg, webp, avif, gif, apng, bmp, tiff, j2k, qoi, ico, tga, exr, pam, ppm |
| 音频 | 7 | mp3, m4a, aac, flac, ogg, opus, wav |
| 视频 | 6 | mp4_h264, mp4_h265, webm_vp9, mkv_h264, mov_h264, avi_mjpeg |

### 矩阵立刻教了我们两件事

1. **APNG 的流 codec 是 `png`**（APNG 基于 PNG，apng 解复用器只负责分帧），不是 `apng`；
2. **ICO 内部是 BMP DIB**（`codec=bmp`），不是 png。

两处都是「我按直觉写的期望值」，被矩阵纠正，已写进测试注释——
这正是当初坚持要跑全矩阵、而不是抽查四个的理由。
