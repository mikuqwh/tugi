# 多水印图层 + 批量处理 — 2026-10-21

> 用户提出两件事：(1) 拖动放大要有丝滑动画，不要突跳；(2) 图片/GIF 水印添加完一个后只能「更换」，
> 应该能继续添加下一个。第 (2) 点确认了口径：**既要同一输出叠多层水印，也要批量处理下一个文件**。
> 状态：已实现、已在真机验证。Commits：`966651f`（动画 + 多图层 + 批量）。

## 一、拖动放大的动画

原来 `_draggingWatermark` 一置位，舞台尺寸当帧跳到 420，视觉上像布局崩了一下。

改成让**封顶值本身**做隐式补间：`TweenAnimationBuilder<double>` 包住舞台，`end: maxStage`，
200 ms `easeOutCubic`。`Tween` 故意不给 `begin`——`TweenAnimationBuilder` 每次都从屏幕上的当前值开始，
所以「放大到一半松手」会从当前高度折返，而不是从头重播。

为什么仍然让它即时响应手指：尺寸是**动画的**，但拖动坐标每次都从 `_frameKey` 的当前盒子算
（`globalToLocal`），所以水印始终贴手指，只有周围的留白在平滑变化。

测试判别力：把 `duration` 改成 `Duration.zero`，用例立刻报
`Expected: a value less than <367.0>, Actual: <372.0>`（即「一步到位」被识别为没有动画）。

## 二、多层水印

### 命令链（一次成片，不是叠 N 次）

`lib/ffmpeg/commands.dart` 新增 `WatermarkLayerSpec` / `WatermarkLayerKind` / `addWatermarks()`，
把 N 个水印编进**一张滤镜图**：

```
[0:v]drawtext=…[b0];                      ← 文字层
[1:v]scale=60:-1,format=rgba[wm1];        ← 图片层
[b0][wm1]overlay=0:0[o1];
[2:v]scale=40:-1,format=rgba,loop=loop=-1:size=8[wm2];   ← 动图层
[o1][wm2]overlay=…:shortest=1[o2];
[o2]split[s1][s2];[s1]palettegen…[s2][p]paletteuse…      ← GIF 输出才有的调色板
```

为什么不逐层各跑一遍：每多一遍就是一次完整重编码——GIF 会被量化两次、视频多掉一代画质，耗时还乘 N。

两条时长规则（都在用例里钉住）：
- **动态源**（GIF/视频）：动图层 `loop=loop=-1` + `overlay … :shortest=1`，输出跟源等长。
- **静态源**：不加 loop、不加 shortest。静态源只有 1 帧，`shortest=1` 会把输出截成 1 帧；
  反过来 loop 则永远不结束。此时靠 `overlay` 默认的 `eof_action=repeat` 冻结尾帧，
  输出长度 = **最长**的那个水印。

输出类型：源是 GIF/视频照旧；源是图片时，只要**任意一层**是动图水印就输出 GIF。

### 屏上

- 新增「水印 n/6」列表：每层一个 chip（类型图标 + 摘要 + ×），点 chip 切换编辑对象；
  「+ 继续添加」复制当前层的类型与尺寸/透明度设置，但内容为空，并自动选中。
- 面板其余部分（类型、文字/图片参数、位置、透明度）一字未改——状态层把单层字段换成了
  「选中层」的 getter/setter，所以旧面板代码自动作用到选中层。
- 预览：N 层按列表顺序绘制；点任一水印即选中并显示玫红选择框；拖动选中层。
  另外保留了一个「空白处也能拖」的透明手势层（在图层下方），因为竖长图上的水印可能只有几像素高。
- 上限 6 层：到顶时按钮变灰而不是消失，避免「为什么点不动」。

### 批量

结果区原来只有「再来一个」，它会把源、文字、水印图全清空——那正是用户抱怨的「只剩一个更改」。
现在多了 **「继续下一个（保留水印）」**：换源文件，水印列表原样保留（位置是比例、字号是百分比，
所以换分辨率也不会跑偏）。「清空重来」保留为显式重置。

## 四、给下一个人的坑

1. `verify3.sh` 里字体必须用**相对路径**（`../wmfont.ttf`）。这台机器的 ffmpeg 是 Windows 二进制，
   给它 MSYS 风格绝对路径 `/d/...` 会**segfault**，而且只打印一行 fontconfig 警告。
   脚本会把 `assets/fonts/NotoSansSC-Regular.ttf` 复制成 `wmfont.ttf`（已 gitignore）。
2. 面板是懒加载 `ListView`：写测试时凡是「读/写面板里的控件」都先 `scrollUntilVisible`，
   而且要**先滚回顶部**再向下找——`scrollUntilVisible` 只朝一个方向滚。
3. 静态源 + 多个动图水印时长度取最长的那个（`eof_action=repeat`）。若以后要精确控制时长，
   需要引入 `-t` 或 `trim`，不是改 overlay 参数能解决的。
